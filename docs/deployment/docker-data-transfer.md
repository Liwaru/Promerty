# Pemindahan data asli Promerty

Panduan ini untuk operator yang mendapat izin pemindahan data. Sumbernya MariaDB lokal `promerty` dan media Laravel. Target pertama adalah schema restore terisolasi pada versi MariaDB VPS yang hendak digunakan.

1. **Buat snapshot baru.** Catat versi source, identitas schema, tabel/engine, FK, view, trigger, routine, event, indeks dan kolom ENUM. Pastikan backup mencakup fitur dan tabel yang benar-benar ada. Inventaris media yang dirujuk serta APP_KEY yang masih dibutuhkan ciphertext. Bekukan mutasi aplikasi, worker, dan upload selama snapshot bersama database dan media. Akun export memakai izin baca/metadata sesuai objek yang terverifikasi.
2. **Ekspor logis.** Gunakan utilitas `mariadb-dump` yang kompatibel. Untuk tabel InnoDB gunakan `--single-transaction --quick --no-tablespaces` dan hindari DDL bersamaan. Sertakan trigger, routine dan event yang ditemukan serta tinjau DEFINER. Gunakan dump satu schema tanpa `--databases` dan tanpa `--add-drop-database`. Jangan menyalin direktori data internal XAMPP. Alirkan dump byte-for-byte langsung ke enkripsi yang telah divalidasi, dengan passphrase hanya lewat Pinentry, staging `.partial`, exit code kedua proses, verifikasi dekripsi dan SHA-256 ciphertext. Gunakan prosedur native Windows yang sebelumnya diuji bila mengekspor dari Windows. Simpan backup dan kunci melalui kanal yang terpisah.
3. **Transfer media.** Buat arsip terenkripsi dan manifest ukuran serta SHA-256. Salin original MP4, turunan yang valid, thumbnail dan gambar publik yang memang dirujuk. Pisahkan disk Laravel `storage/app/private` dan `storage/app/public`. Tolak path traversal dan symlink pada arsip. Pertahankan relative path yang dipakai oleh database, termasuk pemetaan `agent-private/…` ke `storage/app/private/agent-listings/…`. Abaikan fixture, backup lama, log, session/cache filesystem, dan unggahan yang belum selesai. Siapkan volume tujuan terpisah, validasi izin UID 10001 dan hash readback. 
4. **Restore dan bandingkan.** Pastikan identitas server/host/schema dan status target kosong. Gunakan akun import terisolasi dengan privilege minimum sesuai objek. Dekripsi melalui pipe ke client dengan verifikasi TLS tanpa file SQL plaintext permanen. Verifikasi kedua exit code, integritas dekripsi, jumlah tabel/FK, indeks, definisi ENUM, jumlah baris, dan digest data terhadap snapshot terbaru. Bandingkan relasi user/role, cabang, proyek, assignment, listing, post, media, interaksi, pesan, survei, serta audit. Cek tidak ada referensi file putus. Bandingkan SHA-256 asli Tamarama dengan manifest. Jalankan smoke test akses publik/privat, feed, Search, Detail, Range 206, worker, session, dan akun di staging yang disetujui. Tinjau job tertunda dan session dari snapshot sebelum web/worker baru menerima trafik. 
5. **Migrasi terkontrol.** Buat backup target sebelum mengubah schema. Review riwayat `migrations` dan SQL yang akan dijalankan. Gunakan akun migrasi terbatas dan satu eksekusi `php artisan migrate --force` hanya setelah approval. Jangan memakai `migrate:fresh`, `db:wipe`, demo seeder, atau import ulang ke database yang sudah menerima trafik.
6. **Rollback.** Simpan Compose env non-secret, digest image rilis sebelumnya, manifest volume/schema dan backup terenkripsi. Bila rilis gagal sementara schema kompatibel, alihkan edge ke rilis sehat dan jalankan app/web/worker dengan tag lama serta volume yang sama. Jika schema atau data berubah tidak kompatibel, jangan menjalankan downgrade otomatis. Hentikan penulisan, pertahankan bukti target yang gagal, restore snapshot ke target baru, validasi ulang, dan alihkan trafik hanya dengan approval. Jangan hapus volume atau snapshot lama sampai hasil pemulihan dan retensi disetujui.
